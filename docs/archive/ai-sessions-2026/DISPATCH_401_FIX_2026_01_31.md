# Dispatch Admin 401 Fix — January 31, 2026

## Problem

All Dispatch admin pages (Fleet, Clusters, Resources, Virtual Clusters, Propagation, Drift, Costs, Topology) returned **401 Unauthorized** errors. The `/domains` page worked because it used a server-side Next.js API route calling Cloudflare directly.

### Root Cause

Dispatch stored Janua's **opaque `access_token`** in localStorage and sent it as `Authorization: Bearer` to Switchyard's `/v1/admin/*` endpoints. Switchyard's `ValidateExternalToken()` calls `jwt.ParseUnverified()` which fails because opaque tokens are not JWTs.

**Key evidence:**
- `apps/admin-console/app/auth/callback/page.tsx:89` — only stores opaque `access_token`, ignores `id_token`
- `apps/switchyard-api/internal/auth/jwt_external.go:33` — `ParseUnverified()` fails on non-JWT strings
- OIDC scope includes `openid`, so Janua returns both tokens

## Solution: Server-Side API Proxy

All admin API calls now route through Dispatch's Next.js API routes, matching the pattern already working for `/api/domains`.

```
Browser → fetch('/api/admin/fleet')     → Dispatch API Route → fetch(api.enclii.dev/v1/admin/fleet)
          (cookie-authenticated)           (validates cookies)    (Bearer SWITCHYARD_API_KEY)
```

### Benefits
- No token format dependency (server handles auth)
- Single auth boundary (cookies for users, API key for service-to-service)
- No CORS issues (same origin)
- Consistent with existing `/api/domains` pattern
